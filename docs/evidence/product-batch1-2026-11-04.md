# OS integration batch 1 — 2026-11-04

This local development branch is based on upstream `0f03a75351f183c90916962c19ab75a583624627`. It is a product integration candidate, not a GPU release or a publication to Models main.

The public standalone commands remain `raytone-models` and `raytone-models-app`. The OS single-engine tool moves to `raytone-models-legacy`. The native application resolves its own version's CLI and uses `ai.raytone.Models` for both ShellId and AppId. A process lifetime lock and compositor PID/address/stable identity preserve a single window across concurrent launch requests and minimization.

The OS keeps public port 8090 and its existing cloud/local policy. Models' internal router defaults to loopback 19090; `connection.json` may change its internal port but cannot overlap 8090 or the 18000–18999 engine pool. Chat uses that internal connection; Agent configuration retains the public OS endpoint. No provider is switched by install. The OS `raytone_router.models_provider.status()` contract is read-only and not yet activated as a live provider. `status --json` distinguishes no instance, unavailable router, conflict, busy and timeout from readiness. Qt process reads preserve the last good data and expose failures and explicit retry; five real Qt boundary cases are covered by `tests/ui/read-process-probe`.

The user component is installed with `python3 -m raytone_models.user_component install SOURCE`, after OS command migration. Its receipt is `$XDG_DATA_HOME/raytone/models-component/installed.json`. It owns code, wrappers and the desktop entry only. Unknown or modified entries are rejected. Repeated installation is unchanged; `rollback`, `recover` and a persistent interruption record are provided. Model caches, download state, credentials, Agent originals and user recipes are not payload or rollback data. Full cross-component interruption/concurrency and active-task semantics remain batch 5 work.

System components remain a separate deployment. Root code, imports, authorization action and unit require matching root-owned paths and hashes in `/usr/lib/raytone-models/component.json`. The CLI checks these before privileged mutations; the isolated helper also requires the exact protocol and component version, including systemd calls. Missing or mismatched components refuse writes. The package stages its receipt via `scripts/system-manifest` and no longer ships the historical wheel password exemption. No root component was installed in this batch; actual authentication, matching-system success and GPU lifecycle remain batch 4 gates.

Current OS installers refuse source installation on a managed product. The new product manager also rejects an older colliding OS package when Models is installed, before handing work to its older migration code. Direct execution of arbitrary historical immutable installers cannot be made to enforce a newer policy; this is unsupported. Even a shadowing PATH entry cannot change the GUI's fixed CLI. Complete old/new package combinations remain A02/A12 gates.

Validation records and exact candidate/source identities are maintained by the OS project report `tests/scenarios/models-integration-2026-11-04.md`. Eight pages use the real CLI in offscreen render checks; this does not certify mouse behavior, inference or GPU support. Thor wording, shared appearance, Recipes scrolling, field flicker and preview gestures remain later batches. Existing SDDM63 and DEF-001 remain open.
